# Angular compatibility of the collectors

Every Angular API the collectors read, the first version that ships it, and what changed up to Angular 22. The overlay checks each one on the page at runtime (`packages/devtools/src/ng-capabilities.ts`) and sends the result with the page's `pageId` (`report-page-angular`). The versions the panel and the agent tools name come from one table, `ANGULAR_FEATURE_NEEDS` in `packages/devtools/src/config.ts`.

## How this was checked

The `@angular/core` and `@angular/router` packages of these versions were packed with `npm pack` and their fesm bundles read, not run: 12.2.17, 13.4.0, 14.0.7, 14.3.0, 15.0.4, 15.2.10, 16.0.6, 16.1.9, 16.2.12, 17.0.9, 17.1.3, 17.2.4, 17.3.12, 18.0.7, 18.2.14, 19.0.7, 19.1.8, 19.2.25, 20.0.7, 20.1.8, 20.2.4, 20.3.33, 21.0.9, 21.1.6, 21.2.25, 22.0.8 and 22.2.2. "First version" is the first of these that has the API. The `window.ng` keys come from `publishDefaultGlobalUtils` (`globalUtilsFunctions`, and `externalCoreGlobalUtils` in 22), which development builds run at bootstrap. Production builds publish none of them.

## Router internals

`router.ts` reads the Router through `read()` guards, so a field an older router lacks is left out of the report. `navigationTransitions` (whose events the overlay prefers) exists from 15.0; before that the overlay subscribes to `router.events`. The overlay calls `currentNavigation` when it is a function and falls back to `getCurrentNavigation()`, which every version has. `withComponentInputBinding` exists from 16.0 and `ROUTER_OUTLET_DATA` by 19.2 (not in 18.2).

## Not covered yet

- The inventory comes from the packed bundles. CI runs the page-side tests against real Angular 20, 21 and 22 apps, but not yet against 12 to 19; that is the follow-up (issue #386, step 5). The fake `ng` objects in `packages/devtools/src/__tests__/ng-shapes.ts` follow the key lists above.
- The overlay imports `@angular/core/primitives/signals` dynamically for the write hook. That entry exists from 17.0, so a bundler that resolves dynamic imports at build time (webpack in `@angular-devkit/build-angular`) may fail to build an Angular 12 to 16 app with the overlay. Setup on older builders is issue #386, step 6.
- `package.json` still declares `@angular/core >=20` and `@angular/common >=20` as peers. The floor moves once CI tests the older versions.
